## Medium-confidence concerns

### U-Hades-1: query_tree downgrade to NotImplementedError (Lock 3 silent-narrow risk)

The Pythia contract `_meta/contracts/hades-to-nemesis.md` Section 'Output
schema' lines 101-112 defines:

```python
async def query_tree(self, file_path: Path, query_source: str) -> list[dict]: ...
```

tree-sitter-language-pack v1.8 Python API does NOT expose raw Tree nodes
(process() returns ProcessResult only). Hades cycle 1 raises
`NotImplementedError` with explicit substitution-path message. Documented in
handoff to Nemesis. Risk: if Nemesis Wave 3 detector pattern strictly requires
tree-sitter query DSL execution (e.g., for complex nested AST patterns), the
regex fallback may have higher false-positive rate. Mitigation: Nemesis can
combine process() output (symbols/imports/exports/structure) + regex for the
5 Apollo detector patterns; full AST query rarely needed for hardcoded-secret
+ outdated-dependency + missing-auth + unsafe-sql + complex-untested patterns.

**Severity**: medium. **Resolution path**: handoff to Nemesis documents
substitution; Aletheia Wave 3 audit verifies 5/5 detectors fire on NodeGoat
fork per `_meta/contracts/aletheia-wave3-audit.md` line 65-69.

### U-Hades-2: find_callsites regex word-boundary not full AST callsite analysis

Pythia contract `hades-to-pandora.md` Section 'Schema specifics' assumes
`find_callsites` returns precise callsite list. Hades cycle 1 uses regex
`\bSYMBOL\s*\(` over file source. Risk: (1) may match string literal containing
symbol name + paren ("hello(world)" matched), (2) may miss method-style calls
on objects where symbol is attribute (`obj.SYMBOL(...)` is matched, but
language-specific dotted access like `obj::SYMBOL` is NOT covered (Rust + C++ use ::).
Pandora's `analyze_intent` LLM call ranks by file proximity so false positives
get deprioritized.

**Severity**: medium. **Resolution path**: Pandora cycle 2 may add a precision
pass that re-parses each candidate file's structure to confirm calls; Pan
post-Wave 3 hardening pass.

### U-Hades-3: Python 3.14 ambient vs 3.12 production parity

Local venv built on Python 3.14.3 (macOS Apple Silicon ambient). PRD Section
17 locks "Python 3.12+"; 3.14 is forward-compatible but Atlas Wave 3 may
ship Docker image on python:3.12-slim. Risk: minor stdlib API drift between
3.12 + 3.14 (e.g., asyncio.QueueFull semantics, hashlib hash naming). All
Hades code uses stdlib features available since 3.10; should not be material.

**Severity**: low-medium. **Resolution path**: Atlas Dockerfile uses
python:3.12-slim base; CI smoke runs pytest there. If divergence surfaces,
ferry to V1 Orch.

### U-Hades-4: WebSocket cross-loop event_bus publish in TestClient

`tests/test_websocket_smoke.py` test `test_ws_building_events_receives_publish`
opens a TestClient WS connection then attempts to publish from a separate
event loop. Starlette TestClient binds the WS handler to its own loop; the
publish in `loop.run_until_complete(_pub())` runs in a fresh loop. The asyncio
queue used by event_bus subscribers is created lazily inside the WS handler
loop, so cross-loop publish silently drops events. The test asserts only that
the endpoint accepted connection, not that the fanout completed (Pan post-Wave
3 hardening pass should add a real uvicorn-backed integration test).

**Severity**: low. **Resolution path**: Aletheia Wave 3 audit demo flow 3x
consecutive PASS gate exercises real flow via `gh CLI` webhook delivery +
browser WS subscription.

### U-Hades-5: HMAC dedup LRU 1024 entries in-memory, not persistent

`_delivery_cache` OrderedDict stores webhook delivery IDs in process memory.
On pod restart (kubectl rollout), the dedup state is lost; a GitHub webhook
retry within seconds of restart could double-publish. K8s single-replica
+ webhook retries within 30 seconds typical = small window.

**Severity**: low. **Resolution path**: Demeter Wave 3 persists pr_events with
UNIQUE(delivery_id) constraint per `_meta/contracts/hades-to-demeter.md` line
177; database layer is the durable dedup. In-memory LRU is fast-path
optimization only.

### U-Hades-6: ProcessResult.structure walks may include non-canonical nesting

`_walk_structure(items)` recurses into children. For deeply nested classes
(e.g., Python decorator-wrapped class method), nested symbols are emitted
with span coordinates of the nested node. Nemesis detectors typically scan
top-level only. ParsedFile.symbols ends up flat list including nested entries.

**Severity**: low. **Resolution path**: Nemesis filter via `kind == 'class'`
+ top-level span column zero if precision needed.

### U-Hades-7: Demeter stub interface assumes `set_demeter_service` swap pattern

Hades imports `get_demeter_service()` returning Protocol-typed stub. Demeter
worker (parallel spawn batch) needs to invoke `set_demeter_service(real_svc)`
in its initialization to install. Coordination: Demeter handoff log
`wave3_demeter_cycle2_full.md` MUST document the swap call site (likely
inside FastAPI lifespan startup in Hades main.py or Demeter module's own
init function imported at startup).

**Severity**: medium. **Resolution path**: explicit cross-worker handoff in
`_meta/handoff_log/wave3_hades_to_demeter.md`.

### U-Hades-8: OAuth callback files_changed extraction relies on `_files_changed` payload hint

`translate_webhook._extract_files_changed_from_pr` reads
`payload.pull_request._files_changed` (a synthetic field). Real GitHub
webhook payloads include `pull_request.changed_files` (count only, not list);
file list requires a separate `GET /repos/{owner}/{repo}/pulls/{num}/files`
API call. Cycle 1+2 ship with the synthetic field path; real production
flow requires httpx call to GitHub API with OAuth bearer.

**Severity**: medium. **Resolution path**: Pan post-Wave 3 hardening adds
GitHub API fetch for `pulls/{num}/files`; for hackathon demo Hafiz can
inject `_files_changed` via Postman webhook test OR rely on commit-status
event which carries file paths.
