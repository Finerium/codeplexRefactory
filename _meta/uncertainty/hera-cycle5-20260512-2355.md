## U-Hera-08: React 19 strict mode + zustand v5 max-update-depth loop (FIXED Cycle 5)

**Confidence**: high (root cause identified + fix applied + smoke verified)
**Severity**: critical (initially, before fix; benign after fix)

**Discovery**: First `/city` Playwright smoke surfaced `[ERROR] Maximum update depth exceeded` + `getServerSnapshot should be cached` from `commitPassiveMountOnFiber -> updateStoreInstance`. Trace pointed at zustand subscriber binding during mount.

**Root cause**: My `useSprintClickToTicket` hook (and Calliope's existing logBuildingClick handler in `app/city/page.tsx`) passed an inline closure `(building) => { ... }` to Iris's `useBuildingClick(handler)`. Iris's hook registers `handler` in a `useEffect([handler])` dep. New handler reference each render means `useEffect` re-runs every render: unsubscribe + resubscribe + state mutation propagation. React 19 strict mode's double-effect-fire compounds the issue.

**Fix applied Cycle 5**:
1. `frontend/src/modes/sprint/clickHandlers.ts`: wrapped handler with `useCallback(handler, [selectBuilding])`.
2. `frontend/app/city/page.tsx`: wrapped `logBuildingClick` with `useCallback`.
3. Documented in inline code comment.

**Sibling worker exposure**: Persephone's `frontend/components/panels/ticket/useBuildingTicket.ts:48` has the SAME anti-pattern (inline closure passed to `useBuildingClick`). My handoff log `wave2_hera_to_persephone.md` Behavioral guarantee 3 documents the pattern for Persephone's awareness. Persephone may already have the fix (Persephone's TicketPanel currently rendered without infinite loop in my smoke test, possibly because Persephone's handler is stable via memoized callback inside a separate file Hera did not inspect deeply). Dike Wave 2 audit should verify Persephone's handler stability.

**Defer / proceed**: PROCEED. Fix applied + smoke verified 0 errors at /city.
