## Concerns (medium, proceed)

### U-1: GET ?refresh=true blurs HTTP cache-control semantics
GET is supposed to be idempotent + safe. Adding side-effects (cache invalidate + WS emit) on a GET violates REST purist. Demo UX trade accepted. Decision logged D-Phanes-MF2-01. Mitigation: POST /refresh path retained for purist callers + webhook integration.

### U-2: Singleton + event-loop trap surfaces in future tests
The reset_parser_service workaround is local to test fixture. Any future async test that uses TestClient + holds the parser singleton across multiple TestClient contexts will hit the same trap. Long-term fix: refactor parser semaphore to per-loop dict (Hades scope). Deferred.

### U-3: GET ?refresh=true emits WS event on every fetch when client over-triggers
If Selene dashboard hooks the Refresh button to fire too aggressively (e.g. on every focus), the WS topic gets noisy. Mitigation: Selene's `inFlightToken` ref in useDiagramData.ts debounces in-flight. Backend has no rate limit. Phase 2 webhook quota throttle TBD.

### U-4: Repo registry empty beyond `demo`
`datasets/` directory likely empty post-Wave-Fixing #3 clean. Only `demo` registered. Real-repo registration depends on Hades webhook + Triton OAuth + DiagramService.register_repo wire which Cluster A handles. Phanes deferred to Hades cluster for the integration point.
