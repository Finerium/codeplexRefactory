## U-Triton-001: Sentence-transformer model cold start latency on first lookup

**Concern**: `SemanticCache` lazy-loads
`sentence-transformers/all-MiniLM-L6-v2` on first non-stubbed `lookup` or
`store`. Cold start observed at about 4 seconds on M-series MBP (Phase B
research). First production user query incurs this latency on top of the
DeepSeek call.

**Mitigation**:
- Tests use a `_DummyEmbedder` so the model never loads in CI.
- Production deploy: Atlas Wave 3 startup hook can warm the cache by calling
  `get_semantic_cache().store([LLMMessage(role="user", content="warm")], "noop")`.
- If demo rehearsal reveals the first-call lag, switch to a smaller model
  (e.g., `paraphrase-MiniLM-L3-v2`, 17M params vs 22M) at the same threshold.

**Risk**: Demo perception. Demo flow always starts with onboarding tour which
hits canned responses (latency sub-100ms), so the first DeepSeek call is
delayed until later in the flow. Low practical impact.

## U-Triton-002: In-memory llm_call_log buffer loses state on pod restart

**Concern**: `LLMCallLogBuffer` is a `deque(maxlen=1000)` in process memory.
Wave 3 K8s pod restart loses cost aggregate + audit trail.

**Mitigation**:

**Risk**: Demo session resilience. Single 24-hour hackathon window is well
under the typical pod restart cadence. Low practical impact.

## U-Triton-003: Canned response keyword ordering brittleness

**Concern**: `CannedResponseStore.lookup_by_query` does a linear case-
insensitive substring scan. Two demo queries during Cycle 2 testing routed to
wrong entries:
- "Run simulation for 2FA proposal" was hitting the `athena-2fa-proposal`
  entry before the `pandora-simulation-overview` entry because both share the
  "2fa" keyword substring.
- "Show me velocity for sprint 14" missed `selene-velocity-sprint-14` because
  the registered keywords were "velocity sprint 14" / "sprint 14 velocity"
  but the query says "velocity for sprint 14".

**Mitigation**: Cycle 2 reordered the simulation entry before the 2FA proposal
entry + expanded the velocity keywords to include "velocity for sprint". All
10 demo questions now route correctly (pinned by 10-row parametrized test).

**Risk**: Pan post-Wave 3 may add new demo questions; the linear scan can be
ambiguous. Mitigation if regression observed: switch the matcher to a tokenized
scoring approach (e.g., highest keyword-match count wins), or migrate canned
matching to the SemanticCache with a 0.95 threshold. Documented for Pan
awareness.

## U-Triton-004: SSE chunkified response delays first token

**Concern**: Cycle 3 chat endpoint runs a non-streaming LLM call then chunks
into 80-char SSE windows. The user sees the first chunk only after the full
LLM completion is received (about 1 to 3 seconds for V4-Flash, 5 to 15
seconds for V4-Pro think high).

**Mitigation**:
- Canned hits remain sub-100ms via the defensive chain layer 1.
- Persephone UI shows a "Resident is thinking..." indicator during the gap.
- Cycle 4 plan upgrade to native AsyncOpenAI streaming + defensive layer
  preserved is deferred to post-Aletheia if rehearsal shows the delay is
  visible. Decision deferred per Lock 5.

**Risk**: Demo "feel" perception for V4-Pro think-high Athena queries. Apollo
+ Argus + Clio + Hermes (all V4-Flash) stay under 2-second total budget so the
chunked approach reads as a typewriter effect at ingest.

## U-Triton-005: Argus JSON malformed handling falls through silently

**Concern**: `/api/security/argus/score` parses Argus JSON output with two
candidate strategies (direct + first-brace block). On `json_decode_failed`,
the response sets `parse_error` and returns `raw_content` for Nemesis to
re-parse. Nemesis consumer pattern not yet authored (Nemesis Wave 3 Cycle 1
stub-or-real choice unknown).

**Mitigation**:
- Endpoint clamps `cvss_base_score` to [0, 10] when parse succeeds (Lock 5
  honest claim: this is a server-side guardrail; Nemesis can also clamp).
- `raw_content` always preserved so Nemesis can re-parse with a custom regex
  or fall back to a generic "manual review needed" finding flag.

**Risk**: Nemesis's parse logic could collide with Triton's clamp + drop the
score. Mitigation: handoff `wave3_triton_to_nemesis.md` documents both
patterns explicitly.
