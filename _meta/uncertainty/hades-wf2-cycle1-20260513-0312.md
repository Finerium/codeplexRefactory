## Specific uncertainties

### U-Hades-WF2-01: cookie domain semantics in production cluster (MEDIUM)

The `oauth_access_token_enc` cookie is set with `path=/`,
`samesite=lax`, `httponly=true`, `secure=is_production`. In production
the FastAPI service is fronted by Traefik / NGINX ingress at
`duopoly.hackathon.sev-2.com`, so the cookie domain defaults to the
host of the response (production domain) and the subsequent
`/api/repos/list` request from the same origin should carry it
automatically. **Uncertainty**: I have not inspected the K8s Ingress
config for any cookie rewriting; Atlas owns that artifact. If the
ingress strips the Set-Cookie header for any path under `/api/`, the
401 would persist forever.

**Mitigation**: ferry to Atlas if Manager second-pass verify still hits
401 with a fresh OAuth flow. Atlas should `kubectl describe ingress` and
grep for `Cookie` / `Set-Cookie` filter rules.
