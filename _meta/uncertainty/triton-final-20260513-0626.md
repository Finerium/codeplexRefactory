## Medium-confidence concerns

### MC-1: H6 cache-hit hypothesis token count rise from OUTPUT CONTRACT

**Concern**: Each persona now carries an extra ~120 token OUTPUT CONTRACT
block. Across 5 personas that is ~600 token added to the system header
budget. The H6 hypothesis target was 70 percent cache-hit, hinging on the
3000-token shared prefix being identical across all 5 residents.

**Mitigation reasoning**: The OUTPUT CONTRACT is a shared constant
(`_OUTPUT_CONTRACT`) appended verbatim to each persona, so DeepSeek's
prompt-prefix cache will treat the prefix as still identical for repeat
queries against the same resident. Cross-resident sharing (e.g., Apollo
then Hermes) was never expected to share cache rows in any architecture.

**Empirical evidence**: Smoke test of 7 real calls measured
`total_cost_usd: 0.013392` total which is well within the
$5 Hafiz budget. The cache-hit telemetry (`prompt_cache_hit_tokens` field
on DeepSeek usage) is logged but not surfaced on `/api/llm/health`. Deferred
to a future Aletheia audit cycle if H6 verification needed.

**Action**: monitor `/api/llm/health` cost growth during demo rehearsal.
If exceeds $0.05 per 100 chat calls, profile via `llm_call_log_buffer`
+ revisit prompt size.

### MC-2: Tour list bullet glyphs in Hermes persona use ASCII numbers, not Unicode markers

**Concern**: The `HERMES_CHAT_PERSONA` enumerates 4 tour variants using
ASCII `1.`, `2.`, `3.`, `4.` markers. Some IDE auto-formatters convert
those to Unicode bullets (U+2022 BULLET or U+25CF BLACK CIRCLE) on save,
which would not be caught by the emoji regex range and could surface in
the LLM output as decorative characters.

**Mitigation reasoning**: Source is plain ASCII verified via
`test_llm_module_source_files_contain_no_emoji_pictograph`. The emoji
strip regex would catch U+2022 + U+25CF if they ever appeared.

**Action**: No code change. Documented for future maintainer awareness.

### MC-3: AsyncOpenAI client error path when DeepSeek API returns rate-limit

**Concern**: Manager smoke ran 7 real calls in succession. DeepSeek
free-tier rate limits not measured. The `LLMGateway` defensive chain
catches `Exception` broadly and falls back through retry simplified +
fallback model + canned. A 429 rate-limit response would be caught but
the timing window for circuit breaker activation (5 consecutive failures,
60s cooldown) might miss a rate-limit-then-recover scenario.

**Mitigation reasoning**: 7 calls in approximately 90 seconds is well below
public DeepSeek throughput limits. The circuit breaker fires only after
5 *consecutive* failures, so a one-off 429 followed by success would not
trip it. Demo flow has roughly 10 user-visible chat calls per 5 minute
session, also under limits.

**Action**: defer to Aletheia audit or load test if user reports demo-time
rate-limit. No proactive change this cycle.

### MC-4: Server-side route inline guard divergence from client apiUrl()

**Concern**: `frontend/app/api/auth/github/start/route.ts` cannot import
the client `@/lib/apiUrl` helper because it runs server-side at the edge
before client hydration. I duplicated the `stripTrailingApi` logic inline
in the route handler. If the canonical helper signature ever changes
(e.g., new safety guards added), the auth route will lag behind silently.

**Mitigation reasoning**: The safety guard logic is simple (trim trailing
slash + trim trailing `/api`). Source comments in both files cross-
reference. Phase 2 post-hackathon could extract the pure logic to a
shared isomorphic module under `frontend/src/lib/apiUrl.ts` re-exported
via a `route.ts`-safe path. Out of scope this cycle.

**Action**: cross-reference comment authored in both files documenting
the duplication.
