### U4: Marketing route conflicts on body class with Daedalus's dark globals (low confidence, low severity)

**Context**: Daedalus's `app/globals.css` has `@layer base { html, body { @apply bg-codeplex-void text-white; } }`. This applies UNCONDITIONALLY to body. My MarketingThemeLock sets `body.className = ''` and `body.classList.add('marketing-body')`, then marketing.css `.marketing-body { background: var(--bg); color: var(--ink); }` paints over.

**Decision baked**: CSS cascade with class selector (`.marketing-body`) wins over element selector (`body`) due to higher specificity. Verified in Playwright: `bodyComputedBg=oklch(0.96 0.008 240)` (light, not codeplex-void dark).

**Risk**: If a future Tailwind utility class like `bg-codeplex-shadow` gets added to body via another worker, it'll override `.marketing-body`. Mitigation: keep `.marketing-body { background: var(--bg) !important; }` if regression observed. Not added preemptively to avoid violating CSS hygiene.

**Mitigation**: Eunomia audit notes this dependency; Persephone Wave 2 untouched (different route).

### U5: Daedalus `app/layout.tsx` hardcodes `<html className="dark">`, hot-path side effect (medium confidence, low severity)

**Context**: Daedalus's root layout sets `<html className="dark">` server-side. My MarketingThemeLock client component strips it on mount via `classList.remove('dark')`. There is a brief moment between SSR hydration and useLayoutEffect where `dark` class is on html, which may cause Tailwind dark: variants to flash dark before reverting.

**Decision baked**: useLayoutEffect runs synchronously after DOM mutations but before paint. Flash should be sub-frame on M-series. For sensitive cases, could move the lock to a script tag in marketing layout's head or use a non-React inline `<script>` that strips dark class server-side. Skipped for time budget.

**Risk**: Flash of dark on first paint on slow devices. Subjective; not a Lighthouse metric blocker.

**Mitigation**: Pan can wrap MarketingThemeLock logic in a `<script dangerouslySetInnerHTML>` block in layout if observed empirically.
