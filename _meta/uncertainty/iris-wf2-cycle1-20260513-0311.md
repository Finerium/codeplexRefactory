## Open uncertainty items

### U-Iris-WF2-01: Hero count varies with mulberry32 seed (medium)

Hero selection uses `rng() < 0.1` deterministic with seed 20260512. Sampled
hero count at runtime should be ~22 of 220 = 10%. Actual hero count depends
on the building placement loop call order (each `rng() < 0.1` consumes one
draw). If the placement loop early-terminates on `tries < 6000` cap before
reaching N=220, hero count proportionally drops. Marketing landing log
console line "ChronicleCanvas mounted" is not present (cityEngine module
prints nothing). Could add a one-time console.log of heroCount at module
boot for visual demo confidence; deferred unless Manager wants debug
overlay.

Mitigation: trace via DevTools Three.js inspector if needed. The screenshot
confirms heroes ARE visible, count is acceptable.

### U-Iris-WF2-02: Hero spacing vs landmark cluster (low)

The 2.2-4.4 unit wider footprint of hero buildings combined with 9.0 squared
distance threshold means hero placements may reject more often near other
hero placements. Worst case: cluster of heroes are all rejected and pushed
to outer ring. Empirically the screenshot shows heroes distributed across
the city, not clustered. If a future review wants tighter hero distribution
control we could expand reject threshold for hero positions; deferred to
Wave 3 real data feedback.

### U-Iris-WF2-03: setWakeUp triggers per-frame Color.multiplyScalar (low)

Tick runs `entry.material.color.copy(entry.baseColor).multiplyScalar(wakeUpT)`
for each of ~7 wakeUp materials every frame. 7 small allocations + writes
per frame on materials that share buffers across the InstancedMesh.
Negligible perf impact (sub-microsecond per material). Could short-circuit
when `wakeUpT === lastWakeUpT` to avoid the work; deferred as optimization
since Daedalus animation will keep mutating wakeUpT every frame anyway.

### U-Iris-WF2-04: Spire antenna emissive interaction with Bloom (low)

heroSpireMat uses MeshBasicMaterial with toneMapped=false + warm color
`#ffd28a` (RGB ~1.0/0.82/0.54). At full intensity, Bloom luminanceThreshold
~0.6 should pick up the spires. If Daedalus uses different Bloom config
for marketing scene (Calliope ownership not Daedalus), the spires may not
bloom. Marketing landing as-is has NO Bloom (renderer is bare WebGL no
postprocessing per cityEngine.ts line 98). Visual effect is just the
emissive color baked into the cylinder. Acceptable for marketing backdrop
scope; Daedalus /city route has Bloom and would bloom spires there IF
those features were ported to /city scene. NOT in scope.
