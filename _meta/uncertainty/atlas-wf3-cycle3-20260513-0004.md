## U-WF3-C3-03: openspec list returns empty specs array

**Concern**: After A-1 rescue install, GET /api/openspec/list returns `{"specs":[]}` with HTTP 200 + success:true. The binary works (no more 503) but no specs surfaced.

**Root cause**: The container's OpenSpec runtime `cwd` is the project root resolved from `Path(__file__).resolve().parent.parent.parent.parent` which inside container points to `/app/backend/../../..` = `/app` since the backend is mounted at `/app/backend`. The `/app/` directory has no `openspec/` subfolder because the build copies only `/build/backend` + `/build/frontend` artifacts, not the project root `openspec/` folder.

**Risk if demo Day 2 user queries spec list**: empty array surfaces instead of the 17 changes folders + 8 spec items the panitia Folder A holds.

**Mitigation in scope of this cycle**: ferry-gate. Two options:
1. Copy `openspec/` into image (Dockerfile add COPY openspec /app/openspec line) and resolve `cwd` to `/app`. 
2. Mount the project repo as K8s volume (out of hackathon scope for Refactory cluster).

**Decision deferred**: option 1 likely correct fix. Documented for Aether final audit review. Atlas cycle 3 ship criteria did NOT include surfacing real specs (only binary present + 200 not 503), which is now satisfied. Aether final audit can flag as F-1 LOW for cycle 4 follow-up if needed.

**Confidence**: MEDIUM that empty result is acceptable for hackathon ship today; MEDIUM-HIGH that fix is straightforward for follow-up cycle.
