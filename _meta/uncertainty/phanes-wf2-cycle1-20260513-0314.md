## Concern P-2: Edge resolver heuristic miss-rate (medium)

Phase 1 deterministic edge derivation uses Python-style import string parsing (`from foo.bar import baz` then module-path lookup, fallback last-token basename match). Works well for the demo backend (268 edges from 148 files), but:

- TypeScript imports use `from './foo'` relative paths. Heuristic does NOT resolve relative imports.
- Java + Kotlin use `import com.foo.bar.Baz` (fully qualified). The basename-fallback may catch the last segment but module-path lookup will miss because there is no project-root anchor for Java packages.
- C/C++ `#include "foo.h"` is not exposed by tree-sitter-language-pack's `imports` field in the same shape.

**Mitigation**: For demo dataset (Python backend), heuristic is sufficient (268 edges, all valid node ids per test). For multi-language repos at Phase 2 we should add per-language resolvers.

**Confidence**: medium. Phase 1 MVP ship-acceptable; Phase 2 follow-up flagged.
