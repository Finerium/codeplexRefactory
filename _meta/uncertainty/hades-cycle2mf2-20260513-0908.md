## Medium-concern items (uncertainty journal proceed-conservative)

### M1: OAuth token forwarding for private repos

The `repo_clone` helper accepts a `token` kwarg + injects via
`x-access-token:<token>@github.com/...`, but the scan endpoint does NOT
yet decrypt the user's `oauth_access_token_enc` cookie and pass it down.
Implication: private repos owned by the authenticated user cannot be
cloned by the server. Public repos work end-to-end.

Why not fixed in this cycle:
- Wiring cookie -> decrypt_token -> clone helper crosses the
  `app/services/crypto.py` ownership boundary (Hestia).
- The bug-fix scope is the silent-demo-fallback path, not multi-tenant
  private-repo coverage.
- Public repos (including Hafiz's `gadablotnok/web-esp32log`) work; the
  Hafiz repro path is covered.

Handed off to Pan post-submission sweep + flagged in handoff ship report.

### M2: Repo cache filesystem growth

`repo_clone` caches at `<tmpdir>/codeplex-repo-cache/<owner__name>` with no
explicit eviction. For demo session (~2h, <20 repos) the footprint stays
trivial (~50MB total for typical hackathon repos at shallow depth=1).

Mitigation: `evict_repo(repo_full_name)` is exposed for callers that want
to force a fresh clone. Pan can add a periodic sweep if needed.

### M3: Default branch detection

`clone_repo_shallow` lets `--single-branch` default to the remote HEAD,
which is GitHub's default branch (usually `main` but can be `master` or a
custom). Caller can override via `ref=` kwarg. Hafiz repo
`gadablotnok/web-esp32log` defaults to `main` so cycle 2 smoke worked.

Edge case unprotected: a repo whose remote HEAD points to a branch with
no recent commits. Acceptable hackathon risk.

### M4: triggerScan ?demo= broad opt-in

The frontend currently maps any `?demo=<value>` to `{demo: true}` and lets
the backend resolve to NodeGoat. Per PRD 14.1 the demo dataset triplet is
NodeGoat + fastapi-template + PyGoat, but backend `_DEFAULT_DEMO_FIXTURE`
points only at NodeGoat. So three `?demo=` keys all render the same data
under the hood.

DemoSourceBanner already labels this honestly (Lock 5), so the user is
informed. PRD compliance scaffolding for the other two demo datasets is
out of Cluster A scope.

real running uvicorn on `127.0.0.1:8765` with curl. Both showed identical
