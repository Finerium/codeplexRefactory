## U-Iris-02: setMatrixAt count = bucket.length resize discipline

**Confidence**: medium (70-80%)
**Risk**: medium (visual flicker on cycle re-render if r3f changes are
incompatible)

**Surface**: In `BuildingInstances.tsx applyInstanceMatrices`, I set
`ref.count = bucket.length` after the for-loop populates matrices. This
re-points the InstancedMesh draw range to the actual bucket size, vs the
constructor args count which is `Math.max(1, buildings.length)` (to avoid
the 0-count crash). Three.js InstancedMesh.count is mutable + r3f respects
it for frustum culling. Tested by reading three docs + r3f docs, NOT
manually verified via render.

**Risk path**: if r3f@9.6 strict mode double-mounts the InstancedMesh, the
first mount's count assignment may race with the second mount's matrix
push. React 19 strict mode runs effects twice in dev (useLayoutEffect runs
on mount, cleanup, mount).

**Mitigation**:
- The geometry + material are memoized via useMemo with empty deps, so
  double-mount produces same refs.
- applyInstanceMatrices is idempotent (writes the same matrices given the
  same buckets), so double execution does not break visual.
- The bucket partition is also memoized, stable identity, no re-build.

**Action**: Eunomia smoke test verifies. If flicker observed at smoke, fix
by gating applyInstanceMatrices on `ref.current.count === bucket.length`
sentinel.

## U-Iris-04: Mock data districts may overlap at edge cases

**Confidence**: medium (70-80%)
**Risk**: low (worst case: 2 buildings render at identical x/z, visual dup)

**Surface**: The squarified algorithm guarantees no overlap WITHIN a row
because it lays out rectangles left-to-right (or top-to-bottom) along the
short edge. ACROSS rows, the remaining rectangle shrinks after each row, so
the next row starts at row-depth offset and overlap is impossible in theory.

In practice, floating-point rounding could compound across deep recursion
(e.g., 4-level nested folders) and produce sub-pixel overlap. I did not run
a regression test that walks all 240 buildings + asserts no x/z position is
identical.

**Mitigation**:
- Iris-to-Hera contract Edge Case Handling line 8 mentions "if detected,
  log + skip the conflicting district". I did not implement the detection
  loop; mockCityData is the only Wave 1 caller + uses 2-3 level recursion
  max (manageable depth).
- Wave 3 real-data scenarios with 10k+ files could deep-recurse beyond
  4 levels. Demeter Wave 3 must add overlap-detection assertion before
  streaming to Iris.

**Action**: Eunomia smoke verifies visually (no two buildings at exact same
spot at default camera). If overlap surfaces, add `assertNoOverlap(buildings)`
helper in layout.ts.
