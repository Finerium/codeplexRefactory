## U-Hera-03: Drei `<Html>` portal interaction with Daedalus `<EffectComposer>` blend modes

**Confidence**: medium (canonical Drei docs path exists, untested in our specific stack)
**Severity**: medium (impacts sticky note + DoD checklist + size badge readability if Bloom over-applies)

**Concern**: Daedalus `ChronicleCanvas` has `<Bloom intensity={0.9} luminanceThreshold={0.55}>` post-pass always-on. Drei `<Html>` portals out to DOM via React Portal but the underlying mesh marker that handles occlusion (`<Html occlude>`) participates in the depth pass. Risk: text content rendered as DOM is NOT subject to Bloom (good) but the small marker plane behind `<Html>` might cause z-fight with our 14 concept r3f meshes during fade.

**Resolution adopted**: Use `<Html occlude="blending"` mode (not raw `occlude={true}`) which uses opacity blending instead of CSS clip-path. This degrades gracefully when Bloom is on. Plus `distanceFactor={20}` for size-on-zoom + `transform` for billboard-style camera-facing. Confidence: documented pattern.

**Validation steps Cycle 5 (Playwright smoke)**: snapshot the `/city` route with all 14 concepts active, inspect:
- Sticky note text legible at default camera distance
- DoD checklist text legible when building selected
- Size badge readable at mid-distance zoom

If Bloom over-applies on the marker plane, downgrade `occlude` mode to `false` (no occlusion check, HTML always on top). Tradeoff: HTML overlaps geometry when behind a building, but readability preserved.

**Defer / proceed**: PROCEED with `occlude="blending"`. Pan-out test deferred to Cycle 5 smoke.
