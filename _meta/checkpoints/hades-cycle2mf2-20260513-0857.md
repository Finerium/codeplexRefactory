## Scope

Bug #7 Hafiz reporter: repo data inconsistency. User selects own repo on
`/start/pick-repo`, navigates to `/city?repo=<owner/name>`, and Health Mode
panel renders NodeGoat (OWASP) demo findings instead of the user's real
repo. Root cause Hypothesis A confirmed pre-flight by V1 Orch: backend
`backend/app/api/findings/routes.py:238` silently defaulted `repo_root` to
the NodeGoat fixture when the caller omitted it.

Compound root cause discovered during trace:
1. Backend `routes.py:233` defaulted `payload or ScanRequest(...)` so an empty
   POST silently scanned NodeGoat.
2. Backend `routes.py:238` silently substituted `_DEFAULT_DEMO_FIXTURE` when
   `repo_root` was None.
3. No server-side clone infrastructure: there is no path from
   `repo_full_name` to a real filesystem checkout, so even if the frontend
   passed `repo_full_name` the backend could never scan it.
4. Frontend `findingsClient.triggerScan()` defaulted `repo_full_name` to
   `duopoly/codeplex-demo-nodegoat-slice` AND did not pass `repo_root`.
5. Frontend `HealthFindingsVariant` called `triggerScan()` with no args so
   the URL `?repo=` query was never consumed.
