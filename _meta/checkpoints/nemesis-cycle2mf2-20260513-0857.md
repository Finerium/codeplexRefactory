## Bug #7 Cluster F audit findings

Pre-fix `curl -X POST /api/findings/scan` on Hafiz repo `gadablotnok/web-esp32log` (a Deno+TypeScript MQTT logger, NOT NodeGoat) returned a response polluted with canned NodeGoat data:

| Detector | Canned NodeGoat data returned for unrelated repo |
|---|---|
| `outdated_deps` | jquery@1.4.0 + GHSA-2pqj-h3vj-pqgw + package.json:18 |
| `drift_a_stale_closed` | Issue #234 + app/auth/oauth.ts |
| `drift_b_closed_without_merge` | Issue #189 + app/notifications/email.ts |
| `drift_c_spec_impl_lag` | Issue #312 + app/billing/invoice.ts |
| `drift_d_reopened_cycle` | Issue #405 + app/api/upload.ts |
| `drift_e_openspec_drift` | abc123def456 commit + openspec/archive/2026-01-15/add-oauth-flow/ |

Root cause: each detector had an internal `_stub_finding` / `_stub_event` returned when its preferred input was absent (no recognized manifest, no `.codeplex/issues.json` fixture, no openspec/archive). The stub bodies were literal NodeGoat strings designed for cycle 1 smoke, and they kept firing in production because the dispatcher had no guard above them.

Combined with the Cluster A endpoint-level `_DEFAULT_DEMO_FIXTURE` fallback (already removed by Hades), this gave the masquerade: even when the API correctly received `repo_root=/tmp/web-esp32log`, the detectors STILL emitted NodeGoat strings because the user repo had no jQuery manifest and no `.codeplex/issues.json`.

## Fix policy applied

Real-data-only policy. Each detector now:

1. Returns empty list when repo_root invalid (was: NodeGoat stub).
2. Returns empty list when no matching input present (was: NodeGoat stub).
3. The `_stub_*` helper functions remain in source as dead code for the moment (orphan, no callers in production path) so the diff is minimal and reviewable.
4. Detectors retain explicit info-severity records ONLY for honest metadata (`missing_auth_framework_unknown`, `osv_rate_limit_skipped`, `spec_e_git_unavailable`) per Lock 5 honest-claim policy. These records are repo-agnostic and never leak NodeGoat strings.
